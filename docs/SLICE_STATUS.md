## Slice #3 — NDI source picker (auto-discovery + manual URL) (branch `cursor/issue-3-source-picker-2c32`)
**In:** `NDI/NDIDiscovery.{h,mm}` is the durable replacement for `NDIDiscoveryFirstSource` — singleton (`+shared`) with a serial background find loop over `NDIlib_find_wait_for_sources` + `NDIlib_find_get_current_sources`, an `NDISource` value type (`name`, `urlAddress`, `isEqual:`/`hash` defined), `os_unfair_lock`-guarded snapshot, and a main-queue `onSourcesChanged` callback. The find loop owns the find-instance lifetime end-to-end (created in `start`, destroyed inside the loop after `_stopRequested` flips) so `find_destroy` never races the loop's `find_get_current_sources`. `Models/SourceSelection.swift` is the `@MainActor @Observable` Left/Right selection holder with `swap()`. `Models/DiscoveredSources.swift` bridges the ObjC singleton's callback into Observation. `Views/SourcePickerSheet.swift` shows live-updating discovered sources with a manual `ndi://host[:port]/StreamName` entry row that constructs an `NDISource` whose `urlAddress` is `host:port` (default port 5961 if absent) and `name` is `Manual (StreamName)`. `Views/URLParseHelpers.swift` extracts the URL parser as a pure helper for testability — handles IPv6 brackets, percent-decoding, and bare names with spaces. `Views/TopBar.swift` is the always-visible top row: two source dropdowns, a Swap button (disabled when either side is nil), and a disabled gear placeholder. `ContentView.swift` rewritten: `MetalPreviewView` underneath, `TopBar` over the top, an "Pick a source from the top bar" overlay until Left is selected, and `.onChange(of: selection.leftSource)` re-`connect`s / `disconnect`s the receiver. Bridging header now imports `NDIDiscovery.h` (alphabetized: NDIDiscovery, NDIReceiver, NDIRuntime). `NDIDiscoveryFirstSource.{h,mm}` deleted. `stereondiTests/URLParseHelpersTests.swift` covers the spec'd parse cases (host[:port]/name, percent-encoded + bare-space names, rejected schemes, missing parts, leading/trailing whitespace).
**Deferred / HITL:** Build + run on physical iPad with two NDI sources is HITL (no Xcode in CI VM); manual integration test is "switch between two NDI sources via the picker, confirm preview tracks the selection". Right pipeline is unbuilt — Right selection is captured and shown in the top bar but does not affect rendering; `FramePairer` + dual-receiver wiring is a later slice. Auto-hide top bar after 3s is deferred to slice #13. Settings gear is a disabled placeholder (slice #10 wires it). Manual-URL default port is `5961` (NDI's typical first port); a future slice can surface it as user-editable if operators hit non-default deployments.

## Slice #4 — Stereo SbS composite + compositor + golden-image test infra (branch `cursor/issue-4-stereo-sbs-2c32`)
**In:** Two-receiver pipeline now lights up the second eye. `Metal/FrameTypes.swift` defines the `VideoFrameSource` / `VideoFrameReceiving` protocol seams (with `nonisolated` requirements so ObjC `NDIVideoFrame` / `NDIReceiver` conform without isolation friction) and the `StereoFramePair` value type (`@unchecked Sendable` — backing `CVPixelBuffer` is read-only post-create). `Metal/FramePairer.swift` is `@MainActor`, owns a `CADisplayLink` on `.main`/`.common`, and has a public `tick(hostTime:)` so tests can drive it without Metal/UIKit. The display link uses a weak-owner trampoline (`DisplayLinkProxy`) so the pairer isn't pinned alive by `CADisplayLink`'s strong-target retain. `Metal/StereoCompositor.swift` + `Metal/Compositor.metal` implement zero-HIT SbS only: shared `sbs_vertex`, format-specific `sbs_fragment_bgra` and `sbs_fragment_uyvy` (UYVY decoded from `.gbgr422` sampling + BT.709-limited YCbCr→RGB math), per-side aspect-fit into a 960×1080-proportional half via a triangle-strip quad. Pipelines are cached by `(SourceKind, target pixelFormat)` so the same compositor handles both the MTKView's `.bgra8Unorm` and the test target's offscreen `.bgra8Unorm`. `CVMetalTexture` wrappers are pinned via `addCompletedHandler` so the IOSurface backing isn't recycled before the GPU samples it. `Metal/MetalPreviewView.swift` is rewritten — the Coordinator hooks `pairer.onTick` to cache the latest pair + `setNeedsDisplay` the MTKView (which is `isPaused = true, enableSetNeedsDisplay = true`), and `draw(in:)` calls `compositor.render(...)`. `ContentView.swift` now owns two `NDIReceiver`s, a `FramePairer`, and a `StereoCompositor`; left/right `selection.onChange` drive the respective receivers. Test target gains: `HelperToken.swift` (Bundle anchor for Swift Testing free functions), `GoldenImage.swift` (load / write / per-pixel-channel-diff comparison with configurable tolerance), `MetalRenderUtilities.swift` (1920×1080 render-target, 960×540 BGRA gradient pixel buffer, texture readback to `CGImage`, `StubVideoFrame` mock), `StereoCompositorGoldenTests.swift` (`zeroHitSbSGradientPair` — renders red-left / blue-right gradient pair, compares against bundled `Goldens/sbs_zero_hit_gradient.png` at 0.02 tolerance, or rewrites the PNG into `stereondiTests/Goldens/` when `STEREONDI_UPDATE_GOLDENS=1`), `FramePairerTests.swift` (scripted `FakeReceiver` exercising both-sides / left-only / nil-nil / `setReceivers` swap). `stereondiTests/Goldens/README.md` documents the update-goldens workflow and the file-system-synchronized auto-include behavior. No bridging-header / project-file changes.
**Deferred / HITL:** Reference PNG `Goldens/sbs_zero_hit_gradient.png` is **not** committed because Metal isn't available on this Linux CI VM — the user must run `STEREONDI_UPDATE_GOLDENS=1 xcodebuild test -scheme stereondi …` once on a Mac to seed it (see `stereondiTests/Goldens/README.md`); the "test passes via `xcodebuild test`" AC item is HITL-blocked on this single seeding step. Build + run on physical iPad with two live NDI sources confirming the SbS composite is HITL. UYVY sampling format (`.gbgr422` vs `.bgrg422`) is a HITL-verify item — if iPad shows swapped chroma, flip the format binding in `StereoCompositor.drawSide` (shader math is unchanged); see the inline comment. HIT/crop math, anaglyph, channel-test, single-source partial-preview placeholder, and the matching golden tests are explicitly later slices (#6 / #7 / #13). The pairer fires a callback even when both eyes are nil; the compositor renders solid black, which is the slice #4 contract. Resolution-mismatch scaling and stall/zombie detection are slice #11.
