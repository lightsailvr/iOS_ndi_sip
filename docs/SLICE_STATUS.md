## Slice #5 — NDI sender: full-bandwidth SbS output to Quest (branch `cursor/issue-5-ndi-sender-2c32`)
**In:** Output side of the pipeline lights up. `NDI/NDISender.{h,mm}` wraps a single `NDIlib_send_*` instance — `-startWithName:groups:` (idempotent restart), `-sendUYVYFrame:width:height:stride:frameRateNumerator:frameRateDenominator:` (synchronous `NDIlib_send_send_video_v2`, serialized on `os_unfair_lock` so the GPU completion thread + main-thread stop never race), `-stop` (`NDIlib_send_destroy` + matched `[NDIRuntime stop]`). UTF-8 stream-name and groups buffers are owned by the sender (NUL-terminated NSData copies kept alive for the lifetime of the send instance — the SDK doesn't deep-copy the create-struct strings). `clock_video = clock_audio = false` because the FramePairer's `CADisplayLink` is already our clocking source. Bridging header now imports `NDISender.h` (alphabetized: Discovery, Receiver, Runtime, Sender). `Metal/UYVYEncoder.{swift,metal}` is the new compute pipeline — kernel `bgra_to_uyvy_bt709` reads two adjacent BGRA texels per thread, computes per-pixel BT.709-limited Y, averages chroma, and writes packed (U, Y0, V, Y1) bytes into a `device uchar*` buffer at `(y*bytesPerRow + x*4)`. Threadgroup is 16×16 over a `(width/2 × height)` grid via `dispatchThreads` (non-uniform thread groups are universally available on the iPad Pro M-series floor). UYVY destination is an `MTLBuffer` (not a texture) because Metal's `bgrg422`/`gbgr422` formats are read-only on Apple silicon. Even-source-width invariant is a `precondition`. `Metal/StereoCompositor.swift` gains an offscreen 1920×1080 `.bgra8Unorm` render target (`.private` storage, `.renderTarget|.shaderRead` usage, lazily allocated and reused) and a `renderForSender(pair:commandBuffer:) -> MTLTexture?` that delegates to the existing `render(pair:into:commandBuffer:)`. New constants `senderOutputWidth = 1920`, `senderOutputHeight = 1080`. The pipeline cache (keyed on `(SourceKind, targetPixelFormat)`) automatically grows a `.bgra8Unorm` pipeline on first sender frame. `Metal/SenderPipeline.swift` is the orchestrator — owns the `NDISender` + `UYVYEncoder` + a 3-deep ring of `.shared` UYVY MTLBuffers (sized `bytesPerRow * height = 1920*2*1080`). `send(pair:compositor:)` allocates a fresh command buffer on the shared command queue (independent of the on-screen buffer so screen present and network send never block each other), runs `compositor.renderForSender → encoder.encode`, and on `addCompletedHandler` wraps the `.shared` buffer's `contents()` in a `Data(bytesNoCopy:length:deallocator:.none)` — the SDK's synchronous send copies into its internal queue before the closure returns, so the bytes-no-copy lifetime is exactly the call duration. Frame rate hardcoded to 60p (60000/1000) per issue v1 contract; PRD's source-rate matching is slice #14. `start()` re-`-startWithName:groups:` if not running so scene-phase transitions are recoverable. `Metal/MetalPreviewView.swift` adds an optional `senderPipeline: SenderPipeline?` parameter; the Coordinator's `attach(...)` hooks `pairer.onTick` to (a) cache + redraw the MTKView and (b) call `senderPipeline.send(pair:compositor:)`. Both run on the same main-thread tick but on independent command buffers. `ContentView.swift` constructs the `SenderPipeline` alongside the compositor (default stream name `"Stereo Preview"`, groups `"Public"`), threads it through `MetalPreviewView`, and binds `.onChange(of: scenePhase)` to `senderPipeline.start() / .stop()`. `stereondiTests/UYVYEncoderTests.swift` runs four solid-color tests (white → Y=235 / chroma=128, black → Y=16 / chroma=128, red → Y≈63 Cb≈102 Cr≈240, blue → Y≈32 Cb≈240 Cr≈118), all gated on `MTLCreateSystemDefaultDevice() != nil` so Linux CI exits cleanly via `Issue.record`. ±1 LSB tolerance per channel.
**Deferred / HITL:** Build + sign + run on physical iPad with two live NDI sources is HITL — the manual integration tests ("Studio Monitor on a separate Mac shows the SbS composite at correct resolution / framerate"; "Meta Quest with NDI Theater shows the SbS stream as 3D"; "no frame-rate drop on iPad while sending") all require a Mac + iPad + Quest in the same LAN and are not runnable on this CI VM. Stream name + groups are hardcoded for v1 (slice #10 makes them editable from Settings). Source-rate matching for the output stream is slice #14 territory — v1 advertises 60p regardless of actual source rate, which is what the PRD's "v1 always outputs 1920×1080 SbS" allows. Async `NDIlib_send_send_video_async_v2` was rejected for v1 in favor of the simpler synchronous path; revisit if the GPU completion → CPU send hop turns out to add measurable latency. The 3-deep UYVY ring is belt-and-suspenders insurance — the synchronous send copies internally so 1-deep would suffice, but the cost of the extra two buffers (~8 MB total) is irrelevant. Sender lifecycle is wired to `scenePhase` via `ContentView`'s `.onChange`; the existing `stereondiApp.swift` scene-phase NDIRuntime refcount is independent and unchanged.
